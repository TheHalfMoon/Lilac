# P08-G8: desktop resilience

Issue: #230 (P08 umbrella), founder section P08.8: real development packages, build → launch → create/open → edit → save → reopen → source → MCP → crash/recovery → paths → shutdown → cleanup.

**Status:** the release-candidate journey (`scripts/journey-desktop.mjs`, PC gate 17) already covered build through MCP on each platform's packaged app. This grain adds the rest as `scripts/resilience-desktop.mjs`, which runs in the Desktop package workflow on Linux, macOS and Windows. It found one workflow defect, fixed here.

## The resilience journey
It runs the packaged app as a person does (`scripts/desktop/drive.mjs`): a fresh home and projects folder, behind a proxy that records any connection the browser side makes off the computer.
- **The home is `Hôme of Zoë`** and the projects folder **`Design projects – Ωmega 日本`**: spaces, accented Latin, Greek and Japanese in every path Ninerr builds.

| Step | What must hold |
|---|---|
| 1 | The packaged app runs from those folders; a project is created and edited. |
| 2 | A second start exits (code 0) without starting a second Ninerr, and the first goes on taking edits. |
| 3 | The editor's renderer is crashed (Chromium's `Page.crash`). Ninerr reports it and loads the editor again; every layer is there, and the project takes edits. |
| 4 | The app is ended at once, a forced quit with no chance to close. It stops serving; its folder claim and project lock stay behind, both naming the process that was ended. |
| 5 | Started again, it takes the folder over without asking. |
| 6 | The project opens with every committed change. The lock the stopped Ninerr left is taken over without asking, the editor says so, and the takeover is recorded with the project. |
| 7 | The recovered project takes new edits. |
| 8 | Closing the window exits with code 0, stops serving, and removes the project lock and the folder claim. |
| 9 | Nowhere in the projects folder is there a temporary, staging or set-aside file, and the journal ends with a whole line. |
| 10 | Through all of it, the browser side sent nothing off the computer. |

**Locally, Windows 11 (packaged win32-x64 app, Electron 44.7.0):** 10/10. The figures from each platform's CI run are in the PR's qualification record.

## The defect it found: a crash made Ninerr ask about "another session"
- **Before:** after Ninerr was ended at once, the next start took over the projects folder, since the claim's process had stopped (#261). But opening the project then said it is "locked by another Ninerr session", and asked the person to type a reason to take it over. No other session existed: the lock was the stopped Ninerr's own.
- **Fix:**
  - The folder claim now records the computer it was made on. It reports the process id of a host on this computer that stopped without closing since the computer started (`packages/studio-host/src/folder-lock.ts`).
  - Opening a project whose lock names that same process, still not running, takes the lock over at once (`packages/studio-host/src/server.ts`, `session.ts`). The reason "Ninerr stopped without closing (process N)" is recorded with the project, through the same takeover persistence keeps for any other, and the editor shows it.
- **Only that host's locks:** only the locks of the host this one replaced. A lock from an earlier crashed Ninerr still asks.
- **Still asks:** a lock left by any other process, or from before the computer last started, or from a claim made on another computer sharing the folder. A process there may still be writing, and whether it runs cannot be seen from here.
- **Tests:** `tests/folder-lock.test.mjs` covers the takeover, and each case that still asks, with a host process that is killed outright. Hand mutations, each failing its test and then restored:
  - no automatic takeover;
  - a takeover that ignores which process held the lock.

## Also fixed in the test drivers
- `scripts/desktop/drive.mjs` now waits for each launch to exit before removing its folder. On Windows, the files a process still holds cannot be removed.
- It can now:
  - name the home and projects folders;
  - end a launch at once;
  - find the editor again after its renderer was replaced. A crashed page stays dead to the debugging connection, so it connects afresh.

## Not covered
- **A renderer that keeps crashing:** after three reloads in a minute, Ninerr shows an error box and quits. An error box waits for a person, so the journey does not drive it.
- **Bringing the window forward on a second start.** The journey checks that no second Ninerr starts and the first goes on; that the window comes to the front is not observable over the debugging connection.
- **Signing and notarization** of the packages: a founder release-gate item (#139).
