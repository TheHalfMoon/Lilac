# P08-G1: end-to-end journeys

Issue: #230 (P08 umbrella), founder section P08.1.

## What runs
`tests/journeys.test.mjs` runs the five founder journeys through the studio host's own API, as the editor and an MCP agent use it. Each journey runs once per seed. CI runs 3 seeds per journey (`NINERR_JOURNEY_RUNS`, default 3). A failure names its seed, and `NINERR_PROPERTY_SEED=<seed>` replays it.

"Exact state" is the canonical serialization of the document (`serializeDocument`) together with the bytes of the project's journal. After a close and a reopen in a new host, both must be identical. The history panel lists only the changes made since the project was opened, by design (`packages/studio-host/src/session.ts`), so it is not part of the persisted state.

| Journey | Steps | What is checked |
|---|---|---|
| A | create → 40 generated edits, undos and redos → close → reopen in a new host → reopen again → edit | The state is exact after each reopen, the second reopen changes nothing, and the project keeps working. The generated edits cover inserts, renames, text (bidirectional, combining, emoji, multi-line), styles, moves and removes. |
| B | import a page → inspect → edit its text → close → reopen → export the page as JSX, twice | The imported, edited page reopens exactly. The export is deterministic, carries the edit, and no longer has the replaced text. |
| C | connect a codebase → bring a component in → edit → review the diff → write back → edit the file outside Ninerr while it is closed → reopen → reconcile → edit and write back again → reopen | The diff shows exactly the edit, a preview writes nothing, and the file gets exactly the reviewed change. After the outside edit nothing is pending and nothing conflicts. The second write keeps the outside change. The state is exact after reopening. |
| D | connect an agent → MCP `initialize`, `project_info` → the agent creates a frame and retitles the person's text → review the attribution → the agent asks to delete a layer and the person accepts → the person reverts that deletion, undoes the revert, redoes it → close → reopen | The agent's changes are attributed to it, and the deletion waits for the person. The revert, undo and redo each restore the expected document. The state is exact after reopening, and the agent's credential still works. |
| E | a host in its own process → generated edits → a burst of edits → `SIGKILL` once part of the burst is confirmed → a torn write appended to the journal → restart | A stale lock is not taken over without a reason. Every confirmed change survives, and the recovered revision equals the complete journal entries. Nothing half-written is left in the journal. A clean restart reads the very same state, and the project keeps working. |

## Results
- **Locally (Windows):** all five journeys pass with 3 seeds each, and again with `NINERR_JOURNEY_RUNS=10`, 10 seeds each (about 52 s).
- **In CI:** the Foundation run on this PR's head gives the Linux result.

## Found while writing them
- **The history panel is empty after a reopen.** The persisted journal keeps every change, but the panel lists only the changes since the project was opened, so a person cannot see who made the earlier changes. It is filed as a workflow deficiency, #231, and not changed here.
- **Imported text lives in a child text layer.** An imported paragraph keeps its words in a child text node, so an edit to the paragraph element's `text` would not replace them. The journey edits the text layer, as the editor does.
