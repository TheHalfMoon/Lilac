# P08-G1: end-to-end journeys

Issue: #230 (P08 umbrella), founder section P08.1.

## What runs
`tests/journeys.test.mjs` runs the five founder journeys through the studio host's own API, as the editor and an MCP agent use it.
- **Seeds:** each journey runs once per seed, each seed as its own subtest, so a failure names its seed. `NINERR_PROPERTY_SEED=<seed>` replays one, and `NINERR_JOURNEY_RUNS` sets the number of seeds; it must be a positive integer and defaults to 3.
- **Cleanup:** every host a seed starts, in this process or as a child process, is closed or killed in that seed's `finally`, whatever failed.

**Exact state** means two things are byte-identical after a close and a reopen in a new host:
- the canonical serialization of the document;
- every file of the project's store except the lock (`project.json`, `snapshot.json`, `journal.log`), together with the list of stored objects.

The generated sessions (journeys A and E) are checked against a **reference model** written in the test. It shares no code with the host, which applies edits with `@ninerr/history`. It tracks the tree and the props through inserts, prop changes, moves and removes, and undo and redo as snapshots. For every step:
- before every edit, the host's document must have the model's shape;
- the host must accept exactly the edits the model accepts and refuse the others with 400 (a move into the node's own subtree, an index past the end);
- it must undo or redo exactly when the model has something to undo or redo;
- its document must have the model's shape at the end, and again after the reopen.

So a change the host dropped, altered or wrongly refused cannot pass, even when the defect is in `@ninerr/history` itself.

The history panel lists only the changes made since the project was opened, and undo and revert are per session. #231 records this as a deficiency. Journey D asserts the current behaviour, so the test will show when it changes.

## What the journeys found
- **The host could listen on a port browsers refuse.** On a machine whose dynamic port range starts at 1024, three hosts in a row were given ports in 6665–6669. Node's fetch refused them, and Chromium would have too. Fixed in #233: the host never keeps a port on the Fetch standard's bad-port list.
- **A resolved conflict could never be written back.** After the person took the file's value, the field's base stayed stale, so every later change to it conflicted forever. Fixed in #234: such fields are marked as matching.
- **The history panel is empty after a reopen,** and undo and revert are per session: #231. The journal does keep who made each change, with which tool, and what each revert, undo and redo takes back; Journey D reads all three back after the reopen. Only the panel and the session's undo and revert stacks start empty.
- **Imported HTML and imported code keep an element's text in different places:** #235. The exported code is the same either way.
- **A write-back conflict does not say what the two sides are:** it carries only a reason. The person sees "changed both here and in the file", but not the file's value or the base, so cannot compare them before choosing: #236.

## Results
- **Locally (Windows 11, Node 24), on `main` with #233 and #234 merged in:**
  - with the default 3 seeds, all five journeys pass: 20 tests (5 journeys and 15 seed subtests);
  - with `NINERR_JOURNEY_RUNS=10`, they pass 55/55 in 71 seconds.
- **Mutation checks** (each change made by hand, the journey run, the code restored):
  - **Journey C:** without the settle commit of #234, it fails on every seed at "the base advanced to the agreed text". The base stays at the earlier heading.
  - **Journey A:** with `@ninerr/history` ignoring a move's index, it fails on every seed. The host's document no longer has the reference model's shape, and it accepts a move the model refuses.
- **In CI:** the Foundation run at this PR's head gives the Linux result with the default 3 seeds. Longer runs belong to the soak grain (P08-G5), not to CI.
- **Results at this PR's exact head** are in its qualification record.
