# P08: an edit's constant cost halved (#252)

Issue: #252 (an edit costs time in proportion to the whole document). Category: performance, and a workflow blocker. Gate 13's end-to-end edit budget (750 ms at p95, 10,000 layers) had too little margin: it failed in CI runs on Windows (801 ms), on macOS and locally (753 to 983 ms) in the full suite, though each passes alone.

**Status:** the cost per edit is about 43% lower at 10,000 layers. It still grows with the document; the fix that removes that growth is left for the P08 exit gate, as #252 says.

## Where the time went
A CPU profile of 60 one-layer edits on a 10,000-layer project (#252, comment of 2026-10-10) showed that an edit:
- applied its transaction twice (the collaboration room, then the store);
- each time validated the whole input and the whole output;
- each time copied the whole document with `structuredClone`.

`validateDocument` took 42% of the run, and copying 32%.

## The changes
1. **Validated documents are copied directly.** `cloneValidated` (`packages/document-model/src/index.mjs`) copies data that validation accepted: plain objects, arrays and JSON values. It is four times as fast as `structuredClone` on 10,000 layers (32 against 138 ms) and gives the same copy:
   - own enumerable string keys, in their order;
   - `__proto__` kept as an own key;
   - every object a plain one;
   - `-0` kept.

   It replaces `structuredClone` only where a whole, already-validated document is copied:
   - `applyTransaction`;
   - `replayTransactions`;
   - `cloneDocument`.

   Unvalidated input (operations, metadata) is still copied with `structuredClone`, whose refusal of other values is part of those checks.
2. **A store does not re-validate its own document.** A store's document comes only from a validated open, replay or commit, and is never handed out (its getter returns a copy). `applyTransaction` takes `ownValidated` to skip validating such an input. The output is still fully validated, so a bad transaction is refused as before. Every other caller keeps the input check.

## Tests
- **`tests/edit-cost.test.mjs`:**
  - `cloneValidated` equals `structuredClone`, in values and key order, on the cases a plain copy gets wrong (`__proto__`, `constructor`, `-0`, objects without a prototype) and on 200 random documents;
  - skipping a store's input check still refuses a transaction that would make the document invalid;
  - without the option, an invalid input is still refused;
  - a store commits, refuses, keeps its document private and reopens as before.
- **A hand mutation** that drops the `__proto__` case fails the first test, and was restored.
- **The existing suites** (document model, history, persistence, migration, crash recovery, store fuzz, session machine) pass unchanged.

## Not done here
These change the core safety checks, so they need their own grain:
- applying an edit once instead of twice;
- copy-on-write nodes;
- validating only what an edit changes.

They make an edit's cost follow its size, not the document's. #252 stays open for them.
