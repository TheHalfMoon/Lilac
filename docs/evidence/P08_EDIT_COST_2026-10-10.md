# P08: an edit's constant cost halved (#252)

Issue: #252 (an edit costs time in proportion to the whole document). Category: performance, and a workflow blocker. Gate 13's end-to-end edit budget (750 ms at p95, 10,000 layers) had too little margin: it failed in CI runs on Windows (801 ms), on macOS and locally (753 to 983 ms) in the full suite, though each passes alone.

**Status:** the cost per edit is about 43% lower at 10,000 layers. It still grows with the document; the fix that removes that growth is left for the P08 exit gate, as #252 says.

## Where the time went
A CPU profile of 60 one-layer edits on a 10,000-layer project (#252, comment of 2026-10-10) showed that an edit:
- applied its transaction twice (the collaboration room, then the store);
- each time validated the whole input and the whole output;
- each time copied the whole document with `structuredClone`.

`validateDocument` took 42% of the run, and copying 32%.

## The changes
1. **Validated documents are copied directly.** `cloneValidated` (`packages/document-model/src/index.mjs`) copies data that validation accepted: plain objects, arrays and JSON values. It is four times as fast as `structuredClone` on 10,000 layers (32 against 138 ms). For tree-shaped data it gives the same copy:
   - own enumerable string keys, in their order;
   - `__proto__` kept as an own key;
   - every object a plain one;
   - `-0` kept.

   **Where it differs from `structuredClone`:**
   - An object reachable twice in one prop value becomes two copies. No operation edits a nested value in place, so history cannot tell. A store's document never shares, since it is built from JSON. Replay never shares either, so the live document now matches replay more closely.
   - Non-index properties on arrays, and a proxy's being a proxy, are not kept. Neither survives serialization.

   It replaces `structuredClone` only where a whole, already-validated document is copied:
   - `applyTransaction`;
   - `replayTransactions`;
   - `cloneDocument`.

   Unvalidated input (operations, metadata) is still copied with `structuredClone`, whose refusal of other values is part of those checks.
2. **A store does not re-validate its own document.** A store's document comes only from a validated open, replay or commit, and is never handed out (its getter returns a copy). `applyTransaction` takes `ownValidated` to skip validating such an input. The output is still fully validated, so a bad transaction is refused as before. Every other caller keeps the input check. It must stay that way: a document changed after validation and passed with `ownValidated` would have a `Map` or `Date` in it turned into `{}`, not refused.

## Tests
- **`tests/edit-cost.test.mjs`:**
  - for tree-shaped data, `cloneValidated` equals `structuredClone`, in values and key order, on the cases a plain copy gets wrong (`__proto__`, `constructor`, `-0`, objects without a prototype) and on 200 random documents;
  - skipping a store's input check still refuses a transaction only the final validation catches: a restored subtree carrying a node no parent lists;
  - without the option, an input holding a `Map` or a `Date` is still refused;
  - a store refuses that same transaction without writing it, keeps its document private, and reopens as before.
- **Hand mutations, each failing these tests and then restored:**
  - the `__proto__` case dropped;
  - `ownValidated` also skipping the output check;
  - `ownValidated` on by default;
  - the store's getter handing out its own document.

  The first review found that the second and third passed the first version of these tests, whose bad transactions were refused before the final validation. The ghost subtree and the `Map` and `Date` inputs were added for them.
- **The existing suites** (document model, history, persistence, migration, crash recovery, store fuzz, session machine) pass unchanged.

## Not done here
These change the core safety checks, so they need their own grain:
- applying an edit once instead of twice;
- copy-on-write nodes;
- validating only what an edit changes.

They make an edit's cost follow its size, not the document's. #252 stays open for them.
