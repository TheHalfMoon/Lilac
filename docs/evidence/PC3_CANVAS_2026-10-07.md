# PC3: canvas

PC3 adds `@lilac/canvas`: viewport, hit testing, selection and transforms over the PC2 renderer. It closes PC gate 2, the canvas and rendering surface: pan, zoom, selection, hit testing, and incremental re-render from `affectedNodeIds`. It advances gate 3 (document interaction and editing), which PC4 closes through the full editor.

## Design

**The canvas never mutates the document.** Every interaction ends in a list of history operations, passed to `onCommit(operations, intent, { revision })`, where `revision` names the document they were computed from. The editor (PC4) sends these to the studio host as one transaction, and later calls `update(document, affectedNodeIds)`. A drag previews with a CSS `translate` (or a live width and height for a resize) and commits once, on release. That matches the gate-13 design point: no commit per frame.

**Pure parts, tested in Node:**
- **Viewport:** `screen = world × zoom + offset`, with zoom clamped to [0.1, 8]. `zoomAt` keeps the world point under the cursor fixed; `panBy` and `fitBounds` complete it.
- **Selection:** a click replaces the selection, and an extended click (shift, ctrl or meta) toggles. `normalizeSelection` drops ids no longer in the document and any id whose ancestor is selected.
- **Commands:**
  - `moveBy`: a node already absolutely positioned moves by its `left`/`top`; any other node is positioned at its measured offset plus the delta;
  - `resizeTo`, `setStyle`, `setText`;
  - `reorder` among siblings, and `reparent`;
  - `removeNodes`, which removes top-level selected nodes only;
  - `insertNode`.

  Each returns history operations; nothing is applied by the canvas.

**Mounted canvas, `mountCanvas(container, { onCommit, onSelect })`:**
- The sandboxed renderer frame sits in a transformed world layer.
- A transparent capture layer takes the pointer, wheel and keyboard input, so rendered content never receives events (it is also `inert`, from PC2).
- An overlay draws the selection outline and the resize handle in screen space.
- **Hit testing.** A screen point is mapped into world coordinates and then into the frame, and passed to `elementFromPoint` and the renderer's `nodeIdFor`. Inert content is invisible to `elementFromPoint`, so the hit test lifts `inert` for that one synchronous query. No event can be delivered in between.
- **Input:**
  - ctrl or meta plus the wheel zooms about the cursor, and a plain wheel pans;
  - arrow keys nudge by 1, or 10 with shift;
  - Delete or Backspace removes;
  - Escape clears the selection;
  - ctrl or meta with `+`/`-` zooms about the centre.

## Tests

**`tests/canvas-model.test.mjs`** (Node, 3 tests):
- viewport round trips, zoom about a fixed point, the clamps, panning, and fitting with centring;
- selection rules and normalization;
- every command applied through `applyTransaction`. This covers move for positioned and flow nodes (a nested selection is not moved twice), resize (rounded, and positive), style removal, text, reorder (including a clamped no-op), insert, and subtree delete.

**`tests/canvas-browser.test.mjs`** (Chromium, real input, 5 tests; tests 4 and 5 were added in review delta 1):
1. **Selection.** Clicking hits the innermost rendered node, and the selection is drawn. Shift-click extends, and clicking empty canvas clears.
2. **Zoom and pan.** Ctrl+wheel zooms to more than 2.5× with the node under the pointer staying within 2 px. A plain wheel pans by exactly its deltas, and hit testing follows the transformed canvas.
3. **Edits.** Each step's operations are applied through history and then passed to `update`.
   - A drag-move makes no commit while dragging, and commits `Move layer` with the exact new offsets on release. It patches with zero elements created, and the preview is cleared.
   - A resize from the handle commits `Resize layer` with the exact size.
   - The arrow keys nudge by 1, and by 10 with shift.
   - Delete removes the subtree from the document and the canvas, and the selection drops it.

## Catalog

`canvas-viewport` and `selection-transform` move from `planned` to `stub`, owned by `@lilac/canvas`. Canvas-viewport now depends on the renderer. Rotation, grouping, clipping and snapping guides remain planned.

## Accessibility decision

The rendered content is `inert` (PC2), so it is also outside the accessibility tree. The canvas is not the accessible representation of the document. The accessible representation is the editor's layers tree (`role=tree`, PC4), together with the inspector and keyboard commands, and gate 12 (PC8) qualifies it. The canvas stage itself is focusable and takes the keyboard commands listed above.

The hit test lifts `inert` inside `try`/`finally`, so an exception cannot leave the content interactive. It runs on pointer down only, never on pointer move.

## Review delta 1

The security and correctness judge confirmed the pure math, every command applying through `applyTransaction`, and that no document content reaches the parent page. It found three must-fix issues in the mounted canvas, each demonstrated in Chromium. All three are now fixed.

**Fixed:**
- **A drag never ended after a cancelled pointer.** `pointercancel` and `lostpointercapture` now abandon the drag and clear its preview. A move with no button held (a release the page never saw) also cancels.
- **A resize released outside the stage was lost.** Capture was set on the resize handle, which the overlay redraw destroyed. Capture is now held by the stage, which outlives the drag, and all move and up handling happens there.
- **Committed geometry did not match the drag.**
  - A flow node made absolute is now placed by its margin box (its offset minus its computed margin). It keeps its computed width and height, and any `right`/`bottom` is dropped.
  - A resize starts from the computed `width` and `height`, which follow `box-sizing`, so padding and borders no longer inflate it.

**Also taken:**
- **Thresholds.** A press must move 3 screen pixels to become a drag, and a zero delta commits nothing.
- **Previews.** The resize preview is reverted to the document's own inline values when the drag ends, so a refused commit leaves no stale size.
- **Stale edits.** Every commit carries the revision it was computed from, and the editor sends it as the base revision, so an edit computed from a stale document is refused rather than misapplied (PC4). A node deleted while it was being dragged is dropped from the commit.
- **Input filtering.**
  - Only the primary button selects or drags.
  - Arrow keys and Delete with ctrl, alt or meta do nothing.
  - Wheel deltas in lines or pages are converted to pixels, and the zoom step is bounded.
- **Non-finite values.** Viewports reject non-finite offsets, `clampZoom(±Infinity)` clamps to the limits, and a NaN anchor leaves the viewport unchanged. `reorder` of an unknown id returns no operations.

**New tests:**
- **Browser test 4:** a margined flow heading dragged by (10, 0) moves by exactly that and keeps its size. A padded, bordered box resized by (20, 10) grows by exactly that.
- **Browser test 5:**
  - a jittered click commits nothing;
  - a cancelled drag leaves no preview, and a later hover does nothing;
  - a resize released past the stage edge commits, and the element shows the committed size;
  - a right-click does not select.
- **Model tests:** the non-finite cases, a partly positioned node, and an unknown id.
- **Checked against the old code:** with the previous `index.mjs`, five of the eight canvas tests fail.

**Limitation, recorded:** taking a flow node out of flow reflows the nodes around it. If its margin had collapsed through its parent, the parent moves too, and no placement of the node can compensate for that.
