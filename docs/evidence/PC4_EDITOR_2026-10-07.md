# PC4: editor application shell

PC4 adds `@lilac/studio-web`, the browser editor that the studio host serves. It is built over the PC3 canvas, PC2 renderer, history and document model, and the PC1 host. It closes four PC gates:
- **Gate 1, the editor application shell:** opening and creating projects; the layers, inspector and history panels; keyboard operation.
- **Gate 3, document interaction and editing:** insert, move, resize, restyle, text edit and delete, all as history transactions.
- **Gate 4, persistence and reopen:** stale-lock takeover and recovery reported in the UI.
- **Gate 9, mutation attribution, history and undo/redo through the real UI.**

## Host changes

**Serving the editor** (`packages/studio-host/src/server.ts`):
- **What is served.** Only `/packages/<pkg>/src/<file>.(mjs|css|html)` for `studio-web`, `document-model`, `history`, `renderer` and `canvas`. Each path is resolved with `realpath` and must stay inside the packages root. `/` serves the editor page.
- **No token on these files.** They are public source with no secret, so they need no token. The loopback-peer, Host and Origin checks still apply.
- **CSP.** The page gets `default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self' data:; connect-src 'self'; frame-src 'self'; child-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`. Inline styles are allowed because the canvas positions its layers with them.

**Launching.**
- `host.launchUrl()` returns `http://127.0.0.1:<port>/?ticket=<single-use>`. A ticket is 192 random bits, valid for two minutes. Expired tickets are pruned when the next ticket is issued.
- The page drops the ticket from the address bar, then redeems it with `POST /api/launch`. That route requires this host's own `Origin`, and returns the token.
- The token is kept in `sessionStorage`, which is scoped to scheme, host and port, and to the tab. It is sent only as a Bearer header, or in the query of the event stream, since EventSource cannot set headers.
- **Why not a cookie:** browsers scope cookies by host, not port, so a cookie on 127.0.0.1 would also reach every other local server. Bearer requests also leave no CSRF surface.

**Other host additions:**
- `GET /api/history` returns the session's change log: up to 500 summaries since the project was opened, newest last, without operations.
- `GET /api/session` also names the local user, so the history panel can show "You".

## The editor

The editor's document is a read-only copy. It advances only by applying the host's committed change events, in revision order. Those events come from an edit's own response or from the event stream, and duplicates are ignored. A gap, or an event that does not apply, triggers a full refetch. The copy is replaced, never merged.

**Edits:**
- Host calls run one at a time, so each edit's `baseRevision` is the latest revision applied.
- The canvas tags each commit with the revision it was computed from (PC3). An edit computed from a copy that has since moved on is dropped with a message rather than sent.
- When an edit is not applied, the editor calls `canvas.clearPreview()`, so the held drag preview is released (the PC3 contract).

**Panels and dialogs:**
- **Toolbar:** projects, undo, redo, insert box, insert text, delete, zoom out, zoom level, zoom in, fit and save. Each button has its keyboard shortcut in `aria-keyshortcuts`. Insert into an empty project creates a page first.
- **Layers:** an ARIA tree with roving focus. ArrowUp and ArrowDown move, Home and End jump, ArrowRight and ArrowLeft expand, collapse and move to the parent, Enter or Space selects (shift or ctrl extends), and Delete removes. It mirrors the canvas selection both ways.
- **Inspector:** layer name, text, X, Y, width, height, fill, text colour and font size. A field commits on change. A bare number becomes a px length. When a change from elsewhere redraws the panel, a field being typed in keeps its typed value and its focus.
- **History:** each entry shows its intent, its author ("You", or the actor id), an agent marker, the tool and the revision, newest first.
- **Projects dialog:** existing projects and a create form.
- **Lock dialog:** take over a project locked by a session that is gone, with a required reason. The host refuses a takeover while the holder is still alive.
- **Recovery report:** a discarded torn write, removed temporary files, a format upgrade, or a lock takeover.
- **Reopen dialog:** shown when the project's files changed outside Lilac. No filesystem path appears in any dialog.
- **Keyboard:**
  - ctrl or meta with Z undoes, with shift-Z or Y redoes, and with S saves; these are ignored while typing in a field;
  - the canvas handles its own keys (PC3);
  - dialogs are modal `<dialog>` elements and return focus where it was;
  - a skip link jumps to the canvas.

**Accessibility decision (carried from PC3):** the rendered content is inert and outside the accessibility tree. The layers tree, the inspector and the keyboard commands are the accessible representation of the document. Gate 12 (PC8) audits the editor chrome with `auditAccessibility` and the WCAG 2.2 AA checklist.

## Tests

**`tests/editor-browser.test.mjs`:** 6 Chromium tests against a real host on loopback. The serving test (test 4 below) moved to `tests/studio-web-serving.test.mjs` with PC4 part 1 (PR #159), which landed the host side of this grain separately because the full diff exceeded Jev's input limit. Test 5 and the pointer, resize and live-lock steps were added in review delta 1; tests 6 and 7 in delta 2.

1. **Create, edit, undo and redo, save and reopen**, mostly from the keyboard.
   - **Project and ticket:** create a project from the dialog. The ticket is gone from the URL.
   - **Editing, each step committed and checked in the host's document:**
     - insert a box (the page is created with it);
     - restyle it in the inspector;
     - drag it on the canvas with the pointer (committed as one "Move layer");
     - resize it from the handle ("Resize layer");
     - set its position and size back in the inspector, and rename it;
     - insert text inside it and edit the text;
     - select it from the layers tree with the keyboard;
     - nudge it on the canvas with shift-arrow, and check the rendered element moved;
     - undo with ctrl+Z and redo with ctrl+shift+Z;
     - delete the text from the tree.
   - **History:** the panel lists all thirteen changes, newest first, attributed to "You", with their revisions.
   - **Save and reload:** ctrl+S saves. A page reload keeps the session and the document.
   - **Restart:** the host is closed and a new one started on the same projects root. A new launch reopens the project from the dialog, and its document deep-equals what was saved; the tree and the renderer show it.
   - **Isolation:** no request leaves the host's origin, and there are no page errors.
2. **Live changes.**
   - Another client edits the document, and the canvas, history and inspector update from the event stream.
   - A field being typed in keeps its value through a remote change, and its commit does not overwrite that change.
   - A remote delete removes the node from the canvas and the tree, and ctrl+Z (the same person's latest change) brings it back, attributed as "Undo: …".
3. **Lock, crash and reopen.**
   - While another live session holds the project, a takeover with a reason is refused, and the dialog says the holder is still running.
   - A crashed session's lock (a dead pid) and a torn journal tail are set up.
   - Opening the project shows the lock dialog, which refuses a takeover without a reason. Taking over with a reason then shows the recovery report: the 15-byte torn write discarded, and the lock taken over with the reason.
   - Tampering with the journal makes the next edit show the reopen dialog, without any path in it. After the file is restored, Reopen works and editing continues.
4. **Serving (Node).**
   - The page has its CSP, and modules are served as JavaScript.
   - These all return 404: sources outside the browser packages (`.ts` host and persistence files), `package.json` at either level, traversal (`..` and `%2e%2e`), `.git` and a directory. A POST to a static file returns 405.
   - The ticket is refused without an Origin or with a foreign Origin, works once with this host's Origin and returns the token with no cookie, and is refused after use.
   - The API still requires the token.

5. **A change during a refresh is not lost.** The editor's history fetch is held while another client opens a second project and commits two changes. Both reach the canvas, the tree and the history, in order. Against the code before delta 1, this test fails.

**Not covered here, and owned by later grains:**
- Agent attribution with real agent grants arrives with the MCP server (PC5, gate 8). The history panel already renders `actorKind: "agent"` entries with a marker.
- The `undo-conflict` and `stale-revision` refusals are covered at the host level (`tests/studio-host.test.mjs`). The editor shows them as status messages.

## Review delta 1

The security and correctness judge found the security posture sound:
- static confinement and the MIME allowlist;
- Host and Origin checks, including DNS rebinding;
- no CSRF route;
- ticket entropy and single use;
- no markup injection, since every string becomes a text node and node ids reach only `id` and `data-*` attributes;
- the ARIA tree pattern;
- the canvas contract.

It found one must-fix, now fixed.

**Fixed: changes that arrived during a refresh were lost.** A refresh replaced the copy without regard to events seen meanwhile. If another client opened a different project and edited it at once, the editor dropped that edit as "already applied" (compared against the old project's revision), and then installed the new project at an older revision. The fix:
- Change events now name their project, and an event for another project is ignored.
- While a refresh is in flight, events are held. Afterwards they are replayed over the fetched copy; those at or below its revision are already in it, and a gap starts another refresh.
- A `project` event naming a different project invalidates the copy at once.
- A refresh that sees the project change underneath it starts over. (Delta 2 made this hold in every case.)
- New test 5 reproduces the judge's probe.

**Also taken:**
- **Session end.** A 401 at any point after startup (Lilac restarted, or the token was lost) shows the "session has ended" dialog and forgets the token. A stream the browser has given up on is reopened, or the session is reported as ended.
- **Previews.** A failed refresh releases any held canvas preview, so drags never stay blocked.
- **Loading.** Project loads are deduplicated, so the recovery report cannot open twice.
- **Inspector.** The caret position in a field being typed in survives a redraw.
- **Messages.** A change skipped because it was made before the previous one finished says so, instead of blaming another change.
- **Coverage.** Test 1 now drags and resizes through the canvas, and test 3 covers the live-holder refusal. The ticket-pruning wording is corrected.

## Review delta 2

The re-review confirmed the race fix by probe, the held-event replay, and that `requestLoad` and `requestResync` cannot deadlock. It found two must-fix issues in the new logic, both now fixed.

**Fixed:**
- **A project switch during a load could strand the editor.** A second switch while a load was in flight got the stale load back. That load installed the old project name, its refresh then failed the project check, and the retry was skipped because no document was loaded. The fix:
  - a load requested while one is in flight now runs another load after it, so the last request wins;
  - a failed refresh always retries, with a backoff from 250 ms to 30 s that resets on success;
  - invalidating the copy redraws at once.
  - Test 6 reproduces the judge's probe: the host switches to b and back to a while the editor's session fetch is delivered late, and the editor ends on a, at its revision, with all its layers.
- **A refused event stream reconnected in a tight loop.** For example, all 32 slots taken gave about 470 attempts a second. It now reconnects after a delay of 1 s, doubling to 30 s and reset when the stream opens. A reopened stream refreshes the copy, because changes may have been missed. Test 7 holds every slot: the editor makes at most 4 attempts in 3 s, then reconnects once slots free up and follows a project switch.

**Also taken:** `GET /api/document` names its project, and a refresh checks it together with the session's, so one refresh cannot pair one project's document with another project's session.

**Checked against the old code:** both new tests fail against the delta 1 code.
