# P05 D1 - Bidirectional code/design engine implementation evidence

Date: 2026-10-06

Issue: #51

## Scope

First vertical slice of the bidirectional code/design engine: Lilac-owned bounded parsers for a documented JSX/TSX subset, CSS, and Tailwind class preservation; a stable IR with node-to-source provenance; range-anchored AST-aware patches; hunk-based three-way reconciliation that never silently overwrites; both round-trip directions with golden fixtures; and explicit unsupported cases.

Target package:

`packages/code-ir`

## Authority properties

- Adapters read source into IR; they never execute source and never mutate documents.
- Patches transform source text only through verified ranges; mismatches, overlaps, and unknown symbols are conflicts.
- IR metadata is data, never commands; ambiguous reconciliation surfaces conflicts as data with merged null.
- Parsers are bounded (bytes, tokens, depth, symbols, lines) and fail closed; out-of-subset constructs become explicit unsupported regions or typed errors, never guesses.

## Determinism

- Identical sources parse identically; symbol identities derive from content hashes.
- Round-trips are fixpoints on golden fixtures; fingerprints verify stability.
- No clocks or random identifiers in core logic.

Qualification evidence is added to the PR/Issue only after exact-head GitHub CI, Alibaba Open Code Review delegation, and Jev review complete. Cubic, CodeRabbit, and Qodo are not qualification evidence.
